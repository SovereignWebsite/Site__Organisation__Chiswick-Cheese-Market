What the WordPress API gives anyone

A WordPress site describes its own API at /wp-json/. Chiswick Cheese Market's lists 542 routes in 20 namespaces, from WordPress itself (wp/v2) and from its plugins. We called each core content route once (GET, one item, with a browser-style Origin header) and listed the plugin routes without calling them.

Findings

  • All the content is readable without a login: pages, posts, the stallholders (portfolio), their categories, tags and the whole media library (669 files). That is what the six designs are built from.
  • CORS is open. Asked from https://chiswick-cheese-market.organisation.sovereignweb.site, the API answered Access-Control-Allow-Origin: https://chiswick-cheese-market.organisation.sovereignweb.site with Allow-Credentials: true. This is WordPress's default: it echoes back whatever site asks, so a page on any website can read the content in a visitor's browser.
  • Menus need a login (/wp/v2/menus, /wp/v2/menu-items answer 401), so the toolkit reads the navigation from the public homepage instead.
  • The theme's reusable blocks are public (/wp/v2/uncodeblock, 17 items), and so are the pop-ups. The home page's video header lives in one of them.
  • The user list is public: /wp/v2/users answers with 6 accounts. We did not keep or show them. This is common on WordPress; many sites close it, and it is worth a look.
  • 345 declared routes accept writes (POST, PUT, PATCH or DELETE). They all need authentication; we never called them.
  • Plugins add their own namespaces (forms, redirects, SEO, security, an AI assistant, user management, site kit). Their routes are listed below as declared; we did not call any.
